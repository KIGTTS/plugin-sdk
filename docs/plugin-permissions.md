# 插件权限与恢复

API11 将原生插件和Lua项目放入统一管理列表。每个条目可独立启停、编辑/移除以及管理已声明权限。原生清单的 `permissionPurposes` 和Lua manifest的同名字段按权限名说明用途；旧包没有用途说明时显示宿主通用说明。

调用尚未授权的能力时，宿主暂停实际操作，显示“授权”“仅本次允许”“禁用”。允许/禁用持久保存，仅本次只覆盖当前操作；关闭弹窗不放行。后台不弹出新的授权框。原生授权绑定包ID与验签发布者；Lua授权再绑定所属运行时和项目ID，不能共用编辑器权限。Agent的“完全访问”控制任务审批，不代替宿主能力授权，也不能从工具参数伪造批准。

network、app-control、quick-text-read/write、stickers-read/write等在对应SDK入口核验。Lua只能转发本项目已声明、且不超过父运行时能力的请求。网络授权在真实连接前检查；语音引擎、语音包和应用控制各自沿所属插件入口执行。合法项目因等待或拒绝权限不会被当成损坏代码自动停用。

原生DEX插件以应用UID运行，属于可信代码；SDK授权是规范调用门禁，不是操作系统级隔离，不能阻止恶意原生代码绕开SDK使用Java接口。Lua另有库、指令和文件范围限制，也不应称为完整的OS沙盒。

未捕获异常交回系统结束进程；记录异常类型和代码栈，不记录异常消息中的用户文本或密钥。10分钟内累计3次启动早期或插件工作进程致命崩溃，下一次启动进入安全模式，临时不加载所有外部插件。原有启用设置、配置、语音模型和用户数据保留。普通旋转、回收或强制停止不计为崩溃；安全模式在插件管理明确恢复，不自动循环重启损坏进程。

安全模式用于恢复到可操作界面，不能保证所有平台或系统层崩溃都可捕获。通过真实异常处理器、持久记录、正常运行不误计数与恢复测试核验，未用用户数据制造崩溃。

悬浮窗 overlay：提供快捷入口候选及短时文字气泡。首次使用单独请求权限，不随 Agent 完全访问自动授权；添加常驻入口仍需要用户确认。插件不能代开系统悬浮授权或主软件开关。
